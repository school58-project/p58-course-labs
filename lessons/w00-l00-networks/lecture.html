MAC: адрес для доставки рядом

Внутри локальной сети
Сетевая карта использует MAC-адрес.

A4:5E:60:C2:1D:8F
На конверте для соседа
В кадре есть MAC отправителя и получателя. По нему коммутатор выбирает, куда передать кадр.
Кадр — порция данных для передачи внутри одного участка сети.
Адрес интерфейса
Обычный MAC в Ethernet — 48 бит: шесть шестнадцатеричных байтов. Это адрес сетевого интерфейса в канальном сегменте.
Изменяемость
MAC может быть локально назначен или рандомизирован. Он не является постоянным идентификатором человека и не используется для маршрутизации через интернет.

Лекция 15 мин

Как узнать MAC соседа

ARP: учебный диалог
Кто в нашей сети имеет IP 192.168.1.55?
Принтер: «Это я. Мой MAC — D8:3A:DD:77:02:9E».
ARP помогает узнать MAC по известному IPv4-адресу соседа.

Мы отправляем данные на сервер в интернете. Чей MAC нужен сначала?

ARP для IPv4
ARP-запрос ищет MAC локального next hop. Результат кешируется как соответствие IPv4 → MAC.
Удалённый получатель
Для назначения за пределами подсети ищем MAC шлюза. В IPv6 вместо ARP используется Neighbor Discovery. arp -a показывает кеш, а не полный список устройств.

IP: в какой сети искать устройство

192.168.1.0/24
В нашем примере это сеть. Адреса устройств начинаются с 192.168.1.
192.168.1.42
Это адрес ноутбука в этой сети.
/24 показывает границу между частью сети и номером устройства.
Префикс /24
24 старших бита задают сеть. Маска 255.255.255.0, адрес сети 192.168.1.0.

  • Ноутбук подключается к сети и просит настройки.

Discover → Offer → Request → ACK

Трассировка: видимые шаги пути

Демонстрация преподавателя
Windows:       tracert example.com
macOS / Linux: traceroute example.com
  • Строки показывают ответы узлов по пути.
  • Миллисекунды — время до узла и обратно.
  • Звёздочка означает: ответ на пробу не пришёл.
Меньше шагов не обязательно означает быстрее.
Как работает traceroute
Пробы с возрастающим TTL вызывают ответы промежуточных узлов. Показываемые миллисекунды — RTT отдельных проб.
Ограничения наблюдения
Фильтрация и ограничения ICMP могут давать звёздочки. Пути туда и обратно могут различаться. Число ответивших узлов не измеряет пропускную способность.

Лекция 15 мин

TCP и UDP: два способа доставки

TCP: собираем данные по порядку
Нумерует данные, подтверждает получение, повторяет потерянное.

Удобно для сайта, API и передачи файлов.
UDP: отправляем отдельные сообщения
Сам не повторяет потери и не собирает порядок.

Удобная основа для звонков и игр, где важна задержка.
Для нашего сайта и Telegram Bot API дальше разбираем HTTPS поверх TCP.
TCP
Надёжный упорядоченный поток байтов. Подтверждения, повторная передача, управление потоком и перегрузкой. Длительный обрыв приводит к ошибке.
UDP и QUIC
UDP сохраняет границы сообщений, но сам не обеспечивает повторы и порядок. HTTP/3 использует QUIC поверх UDP: надёжность реализует QUIC. «Всё видео идёт по UDP» неверно.
Лекция 14 мин · дополнительно

TCP: начало разговора

SYNХочу установить соединение.
SYN + ACKГотов. Твой запрос получил.
ACKТвой ответ получил. Начинаем.
Это рукопожатие: стороны договариваются о начале соединения.
Three-way handshake
SYN → SYN-ACK → ACK

Стороны согласуют начальные номера последовательности и параметры соединения.
Граница обещаний
ACK подтверждает получение данных TCP-стеком, а не успешное выполнение бизнес-операции. Рукопожатие TCP не шифрует данные и не заменяет TLS.

Лекция 14 мин

Почему localhost виден только мне

127.0.0.1:8000
Приложение принимает соединения только с этого компьютера.
0.0.0.0:8000
Приложение слушает все локальные IPv4-интерфейсы. Доступ ещё зависит от сети и фаервола.
Друг вводит реальный IP вашего компьютера. Адрес 0.0.0.0 в браузер ему давать не нужно.
Bind и connect
127.0.0.1:8000 — слушать только IPv4 loopback. 0.0.0.0:8000 — слушать все локальные IPv4-интерфейсы.
Никакой автоматической публикации
Wildcard-привязка не настраивает фаервол и NAT. Клиент подключается к конкретному адресу интерфейса. IPv6 использует отдельные адреса, например ::1.
